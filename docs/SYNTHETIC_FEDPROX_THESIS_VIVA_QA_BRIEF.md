# Concise Viva Q&A Brief: Proposed Breast-Cancer/FedProx Thesis

**Use:** This is a preparation aid for oral examination. Each response must remain within the documented source-only evidence boundary. It is not a script for claiming approvals, data access, training, performance, clinical relevance, privacy, deployment, or runtime activity.

> **Opening boundary:** “This thesis distinguishes a proposed FedProx study from an executed empirical result. The contribution is documentation-first traceability and default-closed governance; it does not report dataset access, model execution, or empirical performance.”

| Likely question | Claim-safe answer |
|---|---|
| **What is the thesis contribution?** | The contribution is a source-only governance and traceability package that makes the boundary between a proposed breast-cancer/FedProx study and a real empirical result explicit. It records what is documented, what is absent, and what independently governed decisions would have to precede any future study. |
| **Why is FedProx discussed?** | FedProx is treated as protocol context for a future conditional study, not as a completed implementation or result in this project. The thesis uses the context to explain the proposed research direction while preserving the absence of training, inference, metrics, and comparative findings. |
| **Did the project use a breast-cancer dataset?** | No. The supplied public pages were reviewed only for page-level metadata. No dataset asset was downloaded, opened, copied, processed, stored, transferred, trained on, inferred from, or evaluated. Every supplied candidate remains `ineligible` for data use. |
| **Why were the candidates kept ineligible?** | The public-page review did not independently establish the required authority, primary-source provenance and rights, permitted-use conditions, ethics/data-protection requirements, isolated handling design, or prespecified protocol. The project therefore retained a default-closed posture rather than inferring permission. |
| **Does the decision worksheet constitute approval?** | No. It is deliberately blank and non-authoritative. It records fields that a competent independent process might need, but it does not contain an approval, signature, rights finding, ethics outcome, or access authorization. |
| **What did the Hospital Node Agent prove?** | The relevant record supports only the narrow deterministic, source-only local-control behavior described in its completion audit. It does not prove patient-data detection, real upload prevention, data-loss prevention, privacy, hospital integration, deployment, or runtime operation. |
| **How is reproducibility handled?** | The thesis documents a reproducibility and claim-control posture: local evidence is distinguished from absent empirical and operational evidence, and proposed protocol fields are held blank pending independent governance. No executable data/model experiment exists to reproduce in this branch. |
| **Why is there no performance comparison?** | A performance comparison would require a separately governed dataset, prespecified model and evaluation plan, and an executed study. None is present here. Reporting a number or comparator without those conditions would create an unsupported empirical claim. |
| **Is the work clinically validated?** | No. There is no clinical dataset use, clinical workflow, clinical assessment, clinical validation, or clinical-effectiveness evidence in the record. The thesis must not be used to imply a clinical conclusion. |
| **Is privacy guaranteed by the local controls?** | No. The source-only controls are not a privacy proof and do not establish data protection. Privacy, consent, de-identification, and data-protection conditions remain matters for independently accountable review before any future data-use decision. |
| **What would need to happen before empirical work?** | The accountable route is sequential: independent study authority; primary-source rights and permitted-use analysis; applicable ethics and data-protection decisions; approved minimised handling and isolation design; a prespecified protocol; then a separate technical decision. Each gate must be evidenced within its exact scope. |
| **What is the main limitation?** | The core limitation is intentional: no dataset asset, model, training run, inference output, metric, update, submission, aggregation, deployment, or runtime artifact exists. The work is therefore assessed as a governance and traceability contribution, not as a model-performance study. |
| **How did the thesis prevent later documents from overstating earlier work?** | The chronological dossier is the decision authority. Each later document explicitly preserves the earlier evidence state and identifies its own function—editorial, preparatory, source-only, or absent—rather than rewriting earlier records as stronger proof. |
| **What is the final conclusion?** | The thesis demonstrates a defensible way to document a proposed research pathway without converting intent, public metadata, or synthetic local controls into empirical, clinical, privacy, or operational claims. It leaves future empirical work conditional on independent evidence and approval. |

## Oral-response guardrails

Use terms such as **proposed**, **unexecuted**, **public-page metadata only**, **ineligible**, **blank/non-authoritative**, **source-only**, **bounded local evidence**, and **conditional future work**. Do not replace them with “approved,” “validated,” “private,” “secure,” “tested,” “used,” “effective,” “deployed,” “hospital-ready,” or “clinically suitable” unless a separate independently evidenced record supports the exact statement.

If a question asks for a result that does not exist, the appropriate response is: “That evidence is absent from this branch; the thesis records the absence explicitly rather than inferring a result.”
